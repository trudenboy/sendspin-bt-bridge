## Трек 4. 3.1.0-beta.12 — Echo (#476) и диагностика подключения

### 4a. Профили при подключении (полезно для всех «missing sink»)

1. Тест: при подключении `BluetoothManager` логирует INFO одной строкой UUID удалённого
   устройства (из `Device1.UUIDs`) и профили карты PA (активный + доступные), и кладёт их в
   статус устройства (`bt_profiles`), откуда они попадают в диагностику/отчёт.
2. Реализация: `bluetooth/manager.py` (после `ServicesResolved`), чтение профилей карты через
   `services/audio/pulse.py`; поле в `DeviceStatus`/модели API; секция в отчёте
   (`application/diagnostics.py`).

### 4b. Экспериментальный переворот роли A2DP

1. Ключ `EXPERIMENTAL_A2DP_ROLE_FLIP` (bool, по умолчанию false) рядом с
   `EXPERIMENTAL_A2DP_SINK_RECOVERY_DANCE`: схема конфига, миграция не нужна (новый ключ с default),
   настройка в UI в блоке экспериментальных обходов.
2. `bluetooth/device.py`: `disconnect_profile_blocking(uuid)` по образцу `connect_profile_blocking`.
3. В `bluetooth/manager.py`, где сейчас «card is in profile a2dp_source — switching to a2dp_sink»:
   при включённом флаге — `DisconnectProfile(0000110a)` (входящий поток Echo → хост), пауза,
   `ConnectProfile(0000110b)`, повторный поиск sink; одна попытка на подключение, результат в лог
   и в `bt_profiles`.
4. Тесты на фейковом устройстве: флаг выключен → поведение прежнее; включён → порядок вызовов
   Disconnect(110a) → Connect(110b), одна попытка, ошибки не валят подключение.
5. Changelog `### Added` (эксперимент + строка профилей в логе), релиз beta.12, комментарий в #476
   с просьбой к @fozzy010 включить флаг и прислать лог.

Готово, когда: beta.12 вышла; по отзыву либо флаг остаётся/становится автоматическим для
устройств с `a2dp_source`, либо Echo документируется как неподдерживаемые и #476 закрывается.
