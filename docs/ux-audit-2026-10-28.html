UI/UX audit: Sendspin Bridge web UI (v3 beta), 2026-10-28

Scope. I read the Vue 3 SPA on branch v3 (3.1.0-beta.17): ui/src (views, components, kit, stores, i18n en/ru, router), the API it calls, and the docs site. I also read the feat/air-sensor UI diff (/mnt/data/Projects/sbb-airsensor, git diff v3...HEAD -- ui/).

Live checks. I browsed the live instance at http://127.0.0.1:8091 (a standalone desktop bridge with one wired output, "Local Headphones", and no Music Assistant API sign-in). I used widths of 1366 px and 375 px, light and dark, English and Russian. I took no action that plays sound, saves, pairs, scans, restarts or updates. The phone capture page, the measure wizard and the pairing steps were checked by reading the code only.

Severity. - critical: a user cannot finish a core task, or the UI tells them something false. - major: high friction, a risky action, or a WCAG AA failure. - minor: polish.

1. Summary: top 10 issues by user impact

  1. Sign-in is broken (critical). The router and the login page navigate to a route named dashboard, which does not exist.
  2. After a correct password, router.push throws. The catch block then shows "Invalid password. Please try again." and the user stays on the login page.
  3. Opening /login while sign-in is off gives a blank page (screenshot 17).
  4. Evidence: ui/src/router/index.ts:73, ui/src/views/LoginView.vue:42,55.
  5. Status indicators contradict each other (critical). At the same moment, with the same data:
  6. the header says "Music Assistant not connected" and "Music Assistant needs attention";
  7. the speaker card says "Connected to Music Assistant 192.168.10.10";
  8. Diagnostics says "Bridge Health: Healthy" above two warnings;
  9. a recovery item reads "Local Headphones … is disconnected" with the summary "Connected and ready", while the card shows Connected.

The words "connected" and "Music Assistant" cover two different links: the Sendspin audio link and the MA API sign-in. 3. Half of the text ignores the chosen language (major). In the Russian UI, a lot of text still appears in English: - guidance banners, the header status pill and recovery items; - "Why?" reasons and API error messages; - event titles (playback-started), the badges warning/info, the sink state running and the code not_found.

The kit's accessible names are hard-coded English ("Close dialog", "Loading", "Expand sidebar"). The Diagnostics tab labels are evaluated once and do not change when the language changes. 4. Names for the same things are inconsistent (major). - "Release" means "hand the speaker to other devices" in bulk actions, but "free the audio output" in the idle-mode option. The drawer calls that second action "Suspend audio output", and the bulk bar calls it "Power save". - The hand-over feature has six names: Release, Hand over, Handed over, Released, Auto-released, Take back. - The same object is called Speaker, Player or Device; a wired output is shown under "Speakers". - Timing has five overlapping numbers: speaker delay, reported delay, sync error, playout error, and (air-sensor branch) speaker latency and air error. 5. Disruptive actions run with one click and no confirmation or undo (major). - Adapter Power and Reboot in one speaker's Settings tab drop every speaker on that adapter. - Single "Hand over" runs at once, while bulk hand-over asks first. - Disable runs at once. - Config Import replaces the whole configuration immediately. - Restart now and Update now run without warning that playback stops. - Click track: Start and Measure play sound at once, with no warning. 6. Dead ends (major). - The "Restart failed" banner never goes away and offers no next step. - Pairing a speaker and then pressing Cancel leaves it paired but not added, and does not say so. - Recovery items show "→ action" as plain text, not as a button. - In the bug report, Submit stays disabled with no explanation, and the 500 error loading diagnostics only appears in a 4-second toast behind the dialog. - The Logs tab shows "No log entries" when the fetch failed. - The empty Groups page offers "Discover Groups" but no way to create a group. - Cancel is disabled while a measurement records. 7. Accessibility AA failures across the app (major). - The focus ring is primary/50 on white, about 1.6:1 (needs 3:1). - text-warning (#ffa600) is used as text in 13 places, about 1.9:1. - text-secondary on grey fills is 4.2:1, and the guidance summary is 3.7:1. - Disabled cards use opacity-60, which drops all their text below 3:1. - Dialog, drawer and toast close buttons are 16–20 px (needs 24 px). - The single-key shortcuts (1–4, a, /) cannot be turned off (SC 2.1.4). - Error toasts disappear after 4 s. - The group volume slider has no accessible name. 8. Phone layout breaks in places (major). - Diagnostics → Recovery toolbar widens the page to 556 px at 375 px wide (screenshot 19, WCAG 1.4.10). - The drawer's 5 tabs scroll sideways with a visible scrollbar, and "Signal Path" is off-screen. - The header health pill and the runtime row are hidden on phones. - Bulk actions become unlabeled icons, with title tooltips that touch screens never show. 9. Several save models and duplicated features (major). - The device drawer mixes instant toggles (Enabled, Playout sync), instantly applied timing fields, and a form that needs Save. - Closing the drawer discards unsaved edits without a prompt, and no page warns on reload or tab close. - Two calibration tools exist: the per-speaker mic "Measure" and the group sync wizard. - The MA sign-in form exists twice (Groups and Settings). - The update channel can be changed in two places. - The Status and Signal Path tabs repeat sink, codec and format. 10. The docs describe a different UI (major). docs-site/.../web-ui.mdx (and its Russian twin) describe the v2 dashboard: onboarding checklist, "Show checklist", a "Bulk actions" dropdown that targets the whole fleet, and Configuration tabs General/Audio/Devices. None of these exist in v3.

The air-sensor branch adds "Speaker latency (air → sound)" right next to the existing "Speaker delay", plus raw engineering terms (H, PSR, host placement, Locked/Holding) with no explanation.

2.2 Speakers (home), cards, list, bulk actions

# Sev Finding Evidence Recommendation
H1 major Release / Hand over name collision. Bulk "Release" means hand-over (stop managing Bluetooth).
