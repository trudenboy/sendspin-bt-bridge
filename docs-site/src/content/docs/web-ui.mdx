The web interface is available through a direct browser port controlled by **`WEB_PORT`** (default **8080** for standalone installs) and through **HA Ingress** for the Home Assistant add-on. In add-on mode the ingress port is **dynamically assigned by Home Assistant Supervisor** (the add-on manifest declares `ingress_port: 0`), so `WEB_PORT` set inside the add-on is ignored: open the UI from the add-on's Home Assistant sidebar entry. The page updates live, so most changes appear without a refresh. If the connection to the bridge drops, a banner says what you see may be out of date until it reconnects.

The words used in the interface and in this guide follow one [glossary](https://github.com/trudenboy/sendspin-bt-bridge/blob/main/docs/ux-glossary.md): a **Speaker** is a Bluetooth speaker or headset, an **Audio output** is a wired or local sound output, and a **Player** is what Music Assistant sees for either.

## Signing in

![Login page with Home Assistant, Music Assistant, and Password auth tabs](/sendspin-bt-bridge/screenshots/screenshot-login.png)

When authentication is enabled, the bridge shows a dedicated sign-in screen before the dashboard.

| Method | When it appears | Notes |
|---|---|---|
| **Home Assistant** | Always in HA addon mode, or in standalone when the bridge is connected to an HA-backed Music Assistant instance | Uses the HA `login_flow`, including TOTP / MFA |
| **Music Assistant** | Standalone installs already connected to MA with a built-in MA token flow | Validates MA credentials against the connected MA server |
| **Password** | Standalone auth is enabled and a local password hash exists | PBKDF2-SHA256 local password flow |

If Home Assistant requires MFA, the page switches to a **6-digit verification step**. In standalone mode, the **Security** section of Settings controls the session timeout and brute-force policy for these logins. Login forms are CSRF-protected, and standalone sessions use `SameSite=Lax` plus `HttpOnly` cookies.

<Aside type="tip">
After **5 failed attempts** the default lockout is **5 minutes**, but all lockout values are configurable in **Settings → Security**.
</Aside>

## Pages

The sidebar (a bottom bar on a phone) has four pages.

| Page | What it is for |
|---|---|
| **Speakers** | Every speaker and audio output with its live state, the speaker panel, bulk actions and adding a speaker. |
| **Groups** | The Music Assistant sync groups, with **Group sync** for tuning a group together. |
| **Settings** | One page of sections: General, Music Assistant, Audio, Bluetooth, Home Assistant, Security, Updates, Guidance and Backup. |
| **Diagnostics** (**Health** on a phone) | Overview, Logs and System tabs, with the recovery guidance and the event timeline. |

The header shows the bridge name, a status pill (the lead problem, or startup progress), the runtime row (runtime, host name, IP address, uptime, how many speakers have Bluetooth connected), and a preferences menu for language, theme and **Show technical details**. Earlier addresses such as `/devices`, `/ma` and `/settings` still open the right page.

## Connection states

Three names describe a connection, and they mean the same thing in the runtime row, the speaker cards, the speaker panel and Diagnostics:

| State | What it is | Scope |
|---|---|---|
| **Audio link** | The Sendspin stream between a player and Music Assistant. Shows Playing, Up, Other server, Down or Unavailable. | Per speaker |
| **Music Assistant account** | The bridge's sign-in to the Music Assistant API. Shows Signed in, Signed out or Not set up. | Whole bridge |
| **Bluetooth connection** | The Bluetooth link between the bridge and the speaker. Shows Connected, Connecting, Disconnected, Standby, Released, Disabled or Not paired. | Per speaker |

A state is shown with a reason when it is not OK, for example "Released automatically after repeated connection problems" or "The player is on a Music Assistant that is not this bridge's". The Diagnostics verdict and the header pill come from the same list of issues, so they never disagree.

## Speakers

Speakers can be shown as a list (the default on a wide screen) or as cards (always on a phone). Filters narrow the view by sync group and adapter. Select several speakers to set the group volume, mute or pause them, or use the bulk actions menu.

Each card shows the player name, what is playing with progress and artwork, volume and mute, and the states above (only when something is not OK, unless technical details are on). Click a card or row to open the speaker panel.

### Actions run at once, or ask first

Reversible actions run immediately and show an **Undo** button in the toast: **Standby**, **Wake**, **Enable**, **Disable**, mute, **Power save** and **Release**. Actions with real consequences open a confirmation that names what happens (which speakers disconnect, whether playback stops, whether it can be undone): removing a speaker, **Pair again**, resetting an adapter or a Bluetooth pairing, importing a configuration, restarting the bridge and updating it. A long operation such as a scan, a pairing, an update or a measurement shows progress with **Cancel** in one shared place.

Names of the actions:

| Action | What it does |
|---|---|
| **Release** / **Reclaim** | The bridge stops managing the speaker's Bluetooth so a phone or PC can use it; it does not reconnect until you reclaim it. If the bridge released a speaker after repeated connection problems, it says **Released automatically**. |
| **Standby** / **Wake** | Bluetooth is disconnected to save the speaker's battery; the speaker stays in the list until you wake it. |
| **Power save** | The audio output is paused while the Bluetooth connection stays up. |
| **Disable** / **Enable** | A disabled speaker keeps its settings but gets no player. |
| **Use this bridge as the source** | For speakers that another source (a phone) currently controls over Bluetooth. |
| **Remove speaker** | Removes the player from Music Assistant and the Bluetooth pairing. |

When a control is unavailable, it says why and offers the fix.

### The speaker panel

The panel has four tabs that fit a phone:

- **Overview** - the states, the one main action, the **Audio path** from Music Assistant to the speaker and the latest events with a link to **History**. Recovery tools sit in the **Troubleshoot** menu (**Reconnect**, **Pair again**, **Let Music Assistant pair**, **Unmute the audio output**, **Bluetooth details**).
- **Settings** - name, adapter, listen port, **Speaker latency compensation**, idle behaviour and room. Each field saves as you change it and shows **Saved** with **Undo**. Adapter power and reboot are in **Settings → Bluetooth**.
- **Timing** - the one **Speaker latency compensation** value and **Tune with your group →**. The speaker's **Reported latency** (what it says about itself over Bluetooth) is advisory, and a **Bluetooth latency measured** result appears only after a calibration. Playout, air sensor and sync-error details are folded under **Technical details**.
- **History** - the speaker's recent events.

## Groups and sync tuning

The **Groups** page lists the Music Assistant sync groups with their members and now playing. The **Group sync** page (`/sync/<group id>`) is the one place to line a group up: **Tune by ear** (adjust while listening) or **Measure** (record with the phone microphone, which needs HTTPS or `localhost`), with profiles to keep the results. A speaker that is in no sync group is told how to make one. See [Group sync tuning](/sendspin-bt-bridge/group-sync-tuning/).

## Show technical details

The preference **Show technical details** in the header's preferences menu hides or shows signal levels (RSSI), sync counters, resync counts, Playout and air-sensor rows, server IDs, the signal path, and advanced settings. A browser's own choice is remembered in that browser. Until it makes one, the bridge's default applies: **Technical details by default** in **Settings → General** (`SHOW_TECHNICAL_DETAILS`), which is off for new installs and on for installs that already had speakers. In the interface these rows are grouped under **Technical details**.

## Settings

Settings is one page of sections, each saving as you go. A banner offers a restart when a change needs one.

| Section | Purpose |
|---|---|
| **General** | Bridge name, time zone, logging, and the technical-details default. |
| **Music Assistant** | The connection and the bridge's sign-in (finding the server and getting a token), and how players are controlled. |
| **Audio** | PulseAudio latency, codec preference and rescue-streams control. |
| **Bluetooth** | Adapters (rename, power, reboot), paired devices, scan, reconnect policy, signal strength badges and the advanced recovery workarounds. |
| **Home Assistant** | Entities published to Home Assistant, the integration, and room names from areas. |
| **Security** | Sign-in, sessions, brute-force protection and API tokens (standalone only). |
| **Updates** | How the bridge finds and installs new versions. |
| **Guidance** | When the dashboard shows setup and recovery hints. |
| **Backup** | Download a share-safe `config.json`, import one, or edit the file. Importing replaces all settings and speakers, so it asks first and offers to download the current configuration. |

Advanced settings appear with **Show technical details**; they include the `EXPERIMENTAL_*` compatibility toggles described in [Configuration](/sendspin-bt-bridge/configuration/). Rows that cannot work on the current host are disabled with the detected reason.

## Adding a speaker

**Add speaker** (also reachable from the keyboard) opens a dialog. Put the speaker in pairing mode and press **Search**; nearby speakers appear with a signal strength (Strong, Fair, Weak) and say whether another bridge already uses them. Choose one, press **Add**, give it a name and a room, then **Add to bridge**. **Play test sound** plays a short click so you can hear it. A speaker the host has already paired can be picked from **Choose a speaker that is already paired**, and **Speaker not found or pairing fails?** opens the troubleshooting hints. Pairing aids such as **Temporarily disconnect other speakers** are under technical details.

## Diagnostics

**Diagnostics** has three tabs: **Overview** (health summary, recovery guidance with **Run Checks**, and the event timeline with CSV download), **Logs** (filters, auto-refresh, runtime log level INFO or DEBUG, download) and **System** (runtime, adapters, audio backend, and the bridge's own processes). **Submit bug report** pre-fills a description from the diagnostics and previews the attached report. Everything the bridge says in guidance, recovery cards, the header pill, action buttons, timeline events and blocked-control reasons follows the chosen language.

## Home Assistant add-on layout

Inside Home Assistant (Ingress) the page drops the bridge's own header and logo, because Home Assistant already frames it. A compact status pill and the preferences menu stay at the top. **Security** reads "Signed in through Home Assistant" because access is managed there, and **Updates** reads "Updates come from the Home Assistant add-on store". The **Home Assistant** section and room names from areas are available as in standalone mode.

## Updates and bug reports

![Update modal showing current version, target version, release notes, and available actions](/sendspin-bt-bridge/screenshots/screenshot-update-modal.png)

The update badge opens a dialog with the current and target version, the release notes and the actions for your runtime (**Update Now**, **Release Notes**, or a manual hint). **Update Now** asks first: playback stops, and going back means installing the previous version. An update that never finishes says so after three minutes and points to the logs.
